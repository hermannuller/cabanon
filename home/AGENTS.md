# Folder interaction invariants

The user explicitly requires separate click and drag hit areas. Read ../docs/FILE-POINTER-CONTRACT.md before changing file selection, folder views, drag handling, context menus or icon markup.

- Left and right stationary clicks use the whole folder option rectangle, selected or not. Right-click unselected padding opens the FILE menu (latest user table). Movement on unselected padding still starts box selection.
- File dragging starts from icon/name OR the whole already-selected L4 folder option, for both mouse buttons. Only unselected option padding and true background start box selection. fileDragStartHit owns origins; fileContentHit remains width-limited for destinations/double-click/content actions: full option height, continuously from option left edge to visible filename/icon right edge, including top/bottom blank space and the icon/text gap.
- Keep these rules consistent across list, details and paragraph views and both mouse buttons. Do not merge fileDragStartHit, fileClickHit and fileContentHit; only already-selected rows have full-option drag origins.
- Verify relevant changes with the three regression checks named in the contract. Later explicit user requests take precedence.

- Burn is available through Shift+Delete and through Shift while a RIGHT! whitespace box uses delete (latest explicit user request). Box delete executes on release without a prompt; Shift changes its live hint to red burn and requires confirmation. No stationary context menu exposes Burn; any key closes an open menu. Right file dragging always copies. RIGHT! box choices are folder-move, folder-copy, zip-move, zip-copy, delete. See tmp/right-file-actions-check.cjs.
- File drag header targets: one-second hover navigates back/forward/up without ending the gesture; left blank header opens batch Info, right header opens batch rename. New-menu folder/zip targets move for left and copy for right. Invalid header buttons show X. Packed archives own immutable metadata/content snapshots before source removal. Never delete originals from a path-only archive.
- Ctrl+Enter renames one file inline and multiple files in the two-column batch tool. Read ../docs/BATCH-RENAME-SPEC.md; rules execute top-to-bottom, protected /q output is never matched by later FIND, extensions remain unchanged, conflicts cannot overwrite existing entries. Read-only is stored per entry, editable from Info, and must be enforced in content storage and editors.

- File names require a nonempty base name: empty/whitespace and extension-only names must be rejected with the L7 warning `please name it.`. Dismiss this warning on a click anywhere. Keep linked rename, paragraph rename and new-file validation consistent. Regression: tmp/file-base-name-check.cjs.

- Automatic file/folder collision numbering uses `_1`, `_2`, etc., before the extension, without spaces or parentheses. Do not rename existing files as part of applying this rule.

- All file/folder naming entry points use CabanonFilenames in filename-rules.js: NFC, pinned Unicode 15.0.0 default case folding, Windows forbidden characters/devices/endings, 255 UTF-8 bytes per leaf. Automatically remove leading/trailing spaces (including Unicode space characters), preserve interior spaces, and keep rejecting trailing dots. Never trim away Tab, CR, LF, NEL, Unicode line/paragraph separators: reject them anywhere. Do not replace full case folding with toLowerCase. Preserve source content on validation failure. See docs/FILENAME-SPEC.md (repository root) for the naming rules.

- Files in different directories may have identical names. entry.name is the full location path and entry.id owns content. Never restore global leaf-name uniqueness or use a bare file name as a persistent content key. Retain IDs on move/rename and generate fresh IDs on copy. Read ../docs/FILE-STORAGE.md before changing file storage or migration.

- User New file/folder actions and newly packed ZIPs must go through CabanonCreation.create in file-creation.js. Automatic names use the fixed lowercase base new (never the Welcome text, Archive, source name or newone), with _1, _2 … before the extension. All new entries use the shared name typing effect (20ms per grapheme), including paragraph-view text; never animate its icon. Copies/pastes, moves, restores and bundled seeds are excluded from this new-file policy. Explicit Save As names remain user-owned; first-Save and Save-As defaults use new plus the application extension. New blank content must remain empty and blank ZIPs have contents=[]. Read ../docs/FILE-CREATION.md.

- Both mouse buttons spring-open a valid folder after a one-second drag hover, repeatedly into nested folders. Preserve drag source IDs and move/copy semantics; never spring-open self/descendant/invalid targets. Clear all hover timers on cancel/release.
- The wall holds only the protected `/house/holle` folder (label `holle`, square-with-circle icon) and one optional pin. Dragging files/folders onto the wall copies (right) or moves (left) them into `hole`, never onto the wall itself. The hole can be selected and dragged anywhere on the wall (position stored), and double-click opens it like a folder; it cannot be deleted or renamed. Right-clicking the wall, the hole or the pin opens Setting wall / open holle / Show|Hidden / unpin (unpin only with a pin). Test tmp/desktop-hole-check.cjs.
- TXT windows split into 2/3/4 independent empty-document panes with Ctrl+T; a fifth Ctrl+T opens a new window. Drag a pane from the blank area after the last text line (6px threshold) to swap inside the window, join another TXT window, detach, or drop on ×/outside to close. Every textarea always scrolls two extra blank lines below its last line. Window min/max/close must stay right-aligned in every TXT window: keep the `.txt-title-spacer` flex spacer even when a pane toolbar moves out of the title bar. Latest TXT focus override (2026-11-05): only the current pane in the focused window uses L1 content and L4 text; other panes use L2 and L5, like folder panes. An unfocused TXT window uses L2/L5 throughout. TXT title actions are file/edit text menus; new/save/search/editing commands live in the menus (docs/TXT-MENUS.md). The optional status-only L2 bar spans the full width; no right/bottom outer content margin. Test tmp/txt-panes-check.cjs.
- TXT selected text drags with either button: inside the same editor it moves to the drop caret (Word-like, selection follows the moved text); on another folder window's list it creates a .txt named from the first non-empty line (at most 20 characters, forbidden filename characters replaced, collisions numbered) containing exactly the selection. Dropping on the wall does the same inside `/house/holle`; the new file never becomes a wall icon. Escape aborts. RIVER/rive/MARATHON transfers stay right-button only. Test tmp/txt-text-drag-check.cjs and tmp/desktop-text-drop-check.cjs.
- WALL drawing shows no generic drag tether or `Draw` hint; the canvas shows only its own strokes. Test tmp/wall-no-tether-check.cjs.
- TXT accepts file drops: right-dragging any entry, or left-dragging a folder, inserts its full path at the caret (multi-selection joins with newlines); left-dragging a file opens it in TXT. Text drags from RIVER/rive/MARATHON keep their quote behavior. Test tmp/txt-file-drop-check.cjs.
- All pointer drags/selections support Escape as an abort, restoring pre-gesture selection, navigation, geometry and live controls; releasing afterward must perform no drop/click/menu action. gesture-cancel.js must load before pointer handlers and remain the unified cancellation entry. Reversible live controls register rollback callbacks instead of merely hiding the hint.
- Batch rename is a normal resizable/minimizable/maximizable window. Its left column is fixed at 330px. Rules reorder only with CSS chevron buttons on the find header, never by dragging cards. Regression: tmp/gesture-revision-check.cjs.

- Sidebar Control/Alt taps fire on release when no effective action occurred. Pointer motion, wheel scrolling, file clicks and selection boxes (including pressing the modifier while a mouse button is held) do not cancel eligibility. Committed file changes, navigation/window changes, other keys, overlapping modifiers, pointer cancellation, context menus and actual window focus loss suppress the sidebar. Never open during a held mouse gesture. Element-to-element focus changes are not window focus loss. modifier-tap.js captures before consuming handlers; help-shortcuts.js owns the sole invocation. Ctrl+Alt/AltGr never opens a sidebar in either release order.
- Left whitespace selection: Shift temporarily shears the rectangle with frozen width and fixed origin edge; release returns to rectangle. Alt at start locks radial triangle-union sweep; FROM at start locks lasso. Alt/FROM may be released after starting without changing the shape or opening panels. Ctrl still only appends. Both Alt+Ctrl mean radial + append. Shape calculations and wheel locking are restricted to the initial visible viewport, with trajectory samples retained across animation frames. Native FROM key protocol is FROM_DOWN/FROM_UP; standalone toggling lives in selection-shapes.js, not the helper. Test tmp/selection-shapes-check.cjs.

- Batch rename collisions are automatically resolved in the preview and commit with directory-scoped `_1`, `_2`, ... before extensions (2026-10-18 user override). Preserve unselected entries and unchanged selected owners; never overwrite. automaticRenameValues and fileRenameChanges are shared by preview/commit, including selected parents and descendants. FIND syntax errors and invalid output-name errors must be labelled separately. `/a` is valid FIND, `/q` is the output sequence template. Sorting buttons use the same L5 color/opacity and gray hover as action options, even at disabled boundaries. Test tmp/rename-numbering-check.cjs.

- Rename syntax audit: tmp/rename-syntax-audit.cjs verifies documented classes, contiguous patterns, ordinal queries/disambiguation, complements/unions, calendar dates, actions and output templates through model + real keyboard UI + commit. `/c` means CJK letters, excluding punctuation that shares their Unicode blocks; `/i` includes valid nonnumeric/non-English/non-CJK-letter characters and never forbidden filename controls/separators. Empty FIND is a valid global query. Do not claim an unreproduced reported failure is resolved solely because these fixtures pass.

- PNYX and DIAL use the shared CSS app-motion icons (app-motion-icons.css); COLORS remains a CSS color square with a 12-second cycle. Animate only while their containing app button/title is hovered. Leaving pauses at the current phase and reentering resumes; never restore automatic idle animation. Keep these marks consistent in FROM, search, window titles and the taskbar, with pointer-events:none so existing app gestures remain available. Regression: tmp/app-motion-icons-check.cjs.

- User-supplied SVGs replace MARATHON, BLIND, WALL, Ur and WHERE app marks and wall/grid file marks. See icons/manifest.json; keep software WALL/Ur distinct from their wall/tsv file glyphs. Imported SVG style classes must be localized inline to prevent Illustrator st0/st1 class collisions.
- Hole and TXT marks are authored SVGs: `icons/os/hole.svg` (square plus circle), `icons/pdf/txt.svg` (TXT app), and `icons/os/txt-file.svg` (same mark scaled 0.8, no document frame, `.txt` only). Keep `currentColor` and 2px strokes; Phone shares the same manifest assets. Test tmp/txt-icon-check.cjs.

WHERE reveals its dashed route through two bends before showing the destination cross, on hover only. HELP uses inherited icon-color square (brightens on hover like other app icons) / L1 figure with four 500ms frames. SVG detail animations pause/resume with hover; do not replace them with static imports. Regression: tmp/icon-animation-revision-check.cjs.

Software lists, file icons, window titles, taskbar, settings and every other location must stay static even when hovered. Static WHERE shows the complete route/cross, HELP shows frame 1, RIVER shows the staggered logo. Do not restore generic button/title hover playback.
