# Folder interaction invariants

The user explicitly requires separate click and drag hit areas. Read ../docs/FILE-POINTER-CONTRACT.md before changing file selection, folder views, drag handling, context menus or icon markup.

- Left and right stationary clicks use the whole folder option rectangle, selected or not. Right-click unselected padding opens the FILE menu (latest user table). Movement on unselected padding still starts box selection.
- File dragging starts from icon/name OR the whole already-selected L5 folder option, for both mouse buttons. Only unselected option padding and true background start box selection. fileDragStartHit owns origins; fileContentHit remains width-limited for destinations/double-click/content actions: full option height, continuously from option left edge to visible filename/icon right edge, including top/bottom blank space and the icon/text gap.
- Keep these rules consistent across list, details and paragraph views and both mouse buttons. Do not merge fileDragStartHit, fileClickHit and fileContentHit; only already-selected rows have full-option drag origins.
- Verify relevant changes with the three regression checks named in the contract. Later explicit user requests take precedence.

- Burn is available through Shift+Delete and through Shift while a RIGHT! whitespace box uses delete (latest explicit user request). Box delete executes on release without a prompt; Shift changes its live hint to red burn and requires confirmation. No stationary context menu exposes Burn; any key closes an open menu. Right file dragging always copies. RIGHT! box choices are folder-move, folder-copy, zip-move, zip-copy, delete. See tmp/right-file-actions-check.cjs.
- File drag header targets: one-second hover navigates back/forward/up without ending the gesture; left blank header opens batch Info, right header opens batch rename. New-menu folder/zip targets move for left and copy for right. Invalid header buttons show X. Packed archives own immutable metadata/content snapshots before source removal. Never delete originals from a path-only archive.
- Ctrl+Enter renames one file inline and multiple files in the two-column batch tool. Read ../docs/BATCH-RENAME-SPEC.md; rules execute top-to-bottom, protected /q output is never matched by later FIND, extensions remain unchanged, conflicts cannot overwrite existing entries. Read-only is stored per entry, editable from Info, and must be enforced in content storage and editors.

- File names require a nonempty base name: empty/whitespace and extension-only names must be rejected with the L9 warning `please name it.`. Dismiss this warning on a click anywhere. Keep linked rename, paragraph rename and new-file validation consistent. Regression: tmp/file-base-name-check.cjs.

- Automatic file/folder collision numbering uses `_1`, `_2`, etc., before the extension, without spaces or parentheses. Do not rename existing files as part of applying this rule.

- All file/folder naming entry points use CabanonFilenames in filename-rules.js: NFC, pinned Unicode 15.0.0 default case folding, Windows forbidden characters/devices/endings, 255 UTF-8 bytes per leaf. Automatically remove leading/trailing spaces (including Unicode space characters), preserve interior spaces, and keep rejecting trailing dots. Never trim away Tab, CR, LF, NEL, Unicode line/paragraph separators: reject them anywhere. Do not replace full case folding with toLowerCase. Preserve source content on validation failure. See docs/FILENAME-SPEC.md (repository root) for the naming rules.

- Files in different directories may have identical names. entry.name is the full location path and entry.id owns content. Never restore global leaf-name uniqueness or use a bare file name as a persistent content key. Retain IDs on move/rename and generate fresh IDs on copy. Read ../docs/FILE-STORAGE.md before changing file storage or migration.

- User New file/folder actions and newly packed ZIPs must go through CabanonCreation.create in file-creation.js. Automatic names use the fixed lowercase base new (never the Welcome text, Archive, source name or newone), with _1, _2 … before the extension. All new entries use the shared name typing effect (20ms per grapheme), including paragraph-view text; never animate its icon. Copies/pastes, moves, restores and bundled seeds are excluded from this new-file policy. Explicit Save As names remain user-owned; first-Save and Save-As defaults use new plus the application extension. New blank content must remain empty and blank ZIPs have contents=[]. Read ../docs/FILE-CREATION.md.

- Both mouse buttons spring-open a valid folder after a one-second drag hover, repeatedly into nested folders. Preserve drag source IDs and move/copy semantics; never spring-open self/descendant/invalid targets. Clear all hover timers on cancel/release.
- Dragging one folder from its icon/name with either button and releasing on empty desktop space outside its window opens a new folder window at the release point (clamped to 1920×1080). Valid drop targets — folder rows, archives, drag headers, panes, desktop reorder — keep priority, and files or multi-file selections never open windows. The hover hint is the normal light `open new`, not the red X. Test tmp/folder-drag-window-check.cjs.
- TXT selected text drags with either button: inside the same editor it moves to the drop caret (Word-like, selection follows the moved text); on another folder window's list it creates a .txt named from the first non-empty line (at most 20 characters, forbidden filename characters replaced, collisions numbered) containing exactly the selection. Escape aborts. RIVER/rive/MARATHON transfers stay right-button only. Test tmp/txt-text-drag-check.cjs.
- WALL drawing shows no generic drag tether or `Draw` hint; the canvas shows only its own strokes. Test tmp/wall-no-tether-check.cjs.
- All pointer drags/selections support Escape as an abort, restoring pre-gesture selection, navigation, geometry and live controls; releasing afterward must perform no drop/click/menu action. gesture-cancel.js must load before pointer handlers and remain the unified cancellation entry. Reversible live controls register rollback callbacks instead of merely hiding the hint.
- Batch rename is a normal resizable/minimizable/maximizable window. Its left column is fixed at 330px. Rules reorder only with CSS chevron buttons on the find header, never by dragging cards. Regression: tmp/gesture-revision-check.cjs.

- Sidebar Control/Alt taps are release-triggered only when the entire physical key sequence is isolated: no pointer motion/down/up, wheel, other key, overlapping modifier, focus loss or held mouse button. modifier-tap.js must capture before consuming handlers; help-shortcuts.js owns the sole invocation. Ctrl+Alt/AltGr never opens a sidebar in either release order.
- Left whitespace selection: Shift temporarily shears the rectangle with frozen width and fixed origin edge; release returns to rectangle. Alt at start locks radial triangle-union sweep; FROM at start locks lasso. Alt/FROM may be released after starting without changing the shape or opening panels. Ctrl still only appends. Both Alt+Ctrl mean radial + append. Shape calculations and wheel locking are restricted to the initial visible viewport, with trajectory samples retained across animation frames. Native FROM key protocol is FROM_DOWN/FROM_UP; standalone toggling lives in selection-shapes.js, not the helper. Test tmp/selection-shapes-check.cjs.

- Batch rename collisions are automatically resolved in the preview and commit with directory-scoped `_1`, `_2`, ... before extensions (2026-10-18 user override). Preserve unselected entries and unchanged selected owners; never overwrite. automaticRenameValues and fileRenameChanges are shared by preview/commit, including selected parents and descendants. FIND syntax errors and invalid output-name errors must be labelled separately. `/a` is valid FIND, `/q` is the output sequence template. Sorting buttons use the same L6 color/opacity and gray hover as action options, even at disabled boundaries. Test tmp/rename-numbering-check.cjs.

- Rename syntax audit: tmp/rename-syntax-audit.cjs verifies documented classes, contiguous patterns, ordinal queries/disambiguation, complements/unions, calendar dates, actions and output templates through model + real keyboard UI + commit. `/c` means CJK letters, excluding punctuation that shares their Unicode blocks; `/i` includes valid nonnumeric/non-English/non-CJK-letter characters and never forbidden filename controls/separators. Empty FIND is a valid global query. Do not claim an unreproduced reported failure is resolved solely because these fixtures pass.

- PNYX and DIAL use the shared CSS app-motion icons (app-motion-icons.css); COLORS remains a CSS color square with a 12-second cycle. Animate only while their containing app button/title is hovered. Leaving pauses at the current phase and reentering resumes; never restore automatic idle animation. Keep these marks consistent in FROM, search, window titles and the taskbar, with pointer-events:none so existing app gestures remain available. Regression: tmp/app-motion-icons-check.cjs.

- User-supplied SVGs replace MARATHON, BLIND, WALL, Ur and WHERE app marks and wall/grid file marks. See icons/manifest.json; keep software WALL/Ur distinct from their wall/tsv file glyphs. Imported SVG style classes must be localized inline to prevent Illustrator st0/st1 class collisions.

- Authored MARATHON and BLIND SVG details remain hover animated: enlarged 1.8×13 caret blinks; BLIND line wipes left-to-right. WHERE reveals its dashed route through two bends before showing the destination cross, on hover only. HELP uses inherited icon-color square (brightens on hover like other app icons) / L1 figure with four 500ms frames. SVG detail animations pause/resume with hover; do not replace them with static imports. Regression: tmp/icon-animation-revision-check.cjs.

- Latest animation scope override: only FROM pinned app rows (#from #pinned) play icon animations on hover. Software lists, file icons, window titles, taskbar, settings and every other location must stay static even when hovered. Static WHERE shows the complete route/cross, HELP shows frame 1, RIVER shows the staggered logo. Do not restore generic button/title hover playback.

- DOCK override: FROM pinned app rows and DOCK app buttons may animate on hover; all other locations stay static. DOCK marks resolve through canonical app identity, never a premature copy of the title icon. All app marks are 36px with the same baseline as the FROM square; SVG/CSS must use identical geometry. Regression: tmp/dock-icon-audit.cjs opens all apps, checks canonical marks/baselines and hover playback.

- Selected-row origin regression: tmp/selected-row-drag-check.cjs verifies left/right multi-file drags from selected padding in all three views and Escape. tmp/selected-row-drag-unit.cjs checks strict origin/destination separation without a browser. Keep this exception when editing pointer/box rules.

- Batch rename right-preview order changes only from left-dragging the file icon. Reorder sources and recompute /q and duplicate suffix previews immediately; never reorder the folder itself. Escape restores the pre-drag batch order. HELP → Rename documents all implemented grammar/actions/validation and preview ordering; HELP → House documents mouse hit areas, modifiers and shape distinctions. Regression: tmp/rename-order-lasso-help-check.cjs.
- FROM key detection accepts native FROM_DOWN/UP and DOM Meta/OS even in Electron; duplicate down reports are idempotent. At selection pointerdown, lock FROM to lasso with priority over Alt radial. A concave lasso must remove the notch while radial sweep retains previously swept triangles; do not verify only the mode label.

- Latest icon animation override: only DOCK buttons for the currently focused visible application window (.current) animate, without hover. Pause when inactive/minimized or the entire desktop app loses focus. FROM, software lists, title bars and all other locations are complete static marks. This supersedes all earlier hover policies.

- HELP is now an editable plain-text document (help-editor.js/css). Preserve bundled topics when converting legacy help. Full-width topic rows begin at the left window edge; +/− add/remove, double-click renames, and double-click page whitespace enters plain textarea editing. Blur/close preserves a per-profile draft, not the source file. Left save writes the current .help file directly; for untitled documents it opens the folder/name picker. Right-aligned save... always opens Save As. Both use shared creation/storage APIs. All file links use sourceId, same-name files stay independent, read-only blocks editing/overwrite but permits Save As. Title + opens a new unsaved document; all HELP windows share one DOCK app group. Tests: tmp/help-editor-check.cjs and tmp/help-editor-storage-check.cjs.

- Final animation clarification: exactly two playback surfaces: FROM pinned app icons on mouse hover; DOCK icons while their application window is focused, independent of hover. Everywhere else remains static. This supersedes the preceding FROM-static instruction.

- RIVER post right-drag repost is valid only across opposite halves of the originating river-main: left→right or right→left. Same-side, return-to-origin-side and outside targets show the red X and release without composing. Navigation Share/Pub and explicit MARATHON quote targets retain their separate actions; stationary context menus stay unchanged. Use the same canRepost predicate for feedback and release. Test tmp/river-cross-side-repost-check.cjs.

- RIVER big + (.river-write) is an explicit Repost drop target in both one- and two-column layouts. On valid Repost release, focus the compose textarea immediately. Suppress empty-draft hover activation during mouse dragging. A hidden right column does not count as cross-side dropping; single-column users can use + or the unchanged Repost button. Test tmp/river-plus-repost-check.cjs.

- Global Save convention, including all future save controls: after successful Save, display lowercase saved, L6 gray, disabled/non-clickable. Any change to the saved content restores lowercase save and enables it; unchanged view/focus changes do not. Cancellation/failure must not mark saved. Use shared setFileSaveButton from save-button-label.js and real document signatures/success paths, not a generic click timer. Applied to HELP, WALL and MARATHON; test tmp/saved-button-state-check.cjs.

- FROM right-side pinned/recent files use exactly these context actions/order: open, open path, unpin, to wall, info. FROM pinned folders use open, unpin, to wall, info (no open path). open path opens the containing folder; unpin removes list membership/history only, never the source entry; to wall uses the existing desktop-link policy. Do not replay FROM file menus as generic folder entries or append generic Pin/To wall actions. Test tmp/from-pin-menus-check.cjs.

- COLORS is the only playback-state exception: idle is a static currentColor square everywhere, regardless of focus/hover. While playing, only FROM pinned and DOCK marks run the 12-second color cycle, regardless of focus/hover; every other location stays monochrome. colors-playback.js listens to COLORS-owned media playing/pause/ended/emptied/error/removal and exposes CabanonColorsPlayback.setPlaying for the future player. Do not invent a playing state merely because COLORS is opened. Test tmp/colors-playback-icon-check.cjs (including real audio playback events).

- Definitive hit-area table: both stationary left and right clicks cover the entire folder option, selected or not. For movement, unselected origins and all folder/ZIP destinations use a continuous rectangle from option left to visible icon/name right, at full option height (including top/bottom blank space and icon/text gaps). Selected L5 origins expand across the full option width, for both buttons. Only the remaining right-side width or true background starts boxes; paragraph items may have no internal right-side blank width. Never revert to separate glyph/text vertical contours. Test tmp/full-height-file-hit-check.cjs.

- All current and future Cabanon file first-Save/Save-As windows must use openSaveFileDialog in save-file-dialog.js. See ../docs/SAVE-FILE-DIALOG.md. Filter to applicationFileFormats plus navigation folders; support Delete-to-recycle within the list. MARATHON/CANAL is excluded until separately specified.

- Every on/off control uses the shared paintOnOffToggle/settingTextToggle rendering: literal on/off stays fixed, active text is L5 and inactive text L6, only colors change. No swapping single on/off labels or checkbox exceptions. Mixed bulk states keep both dim with aria-pressed=mixed; first click sets all off. Preserve label position.

- Closing an editor with unsaved document content must use confirmDocumentClose: wanna save on line 1, filename plus ? on line 2, save / quit / cancel. Focus save by default. Only close after confirmed save success; failed save or cancelled Save As leaves the document open. TXT, HELP, WALL and MARATHON share this prompt. File-location pickers themselves do not prompt.

- Every user-visible file deletion must call performFileRemoval before mutating entries, including Delete/Shift+Delete, paragraph selection removal, batch/right-box actions and save-picker Delete. Keep rows mounted until the animation promise settles. Source removal during move/archive operations stays synchronous and is not a deletion gesture.

- Paragraph view override: Enter always inserts a line break before the current/selected file, irrespective of caret position; repeated Enter moves it down another row. Double click opens the file, never selects its base name. F2 base-name selection is removed; use single-click base text for editing. The whole icon column — from the name's right edge through the 24px icon, including the gap, at any height inside the 56px row — selects the whole file, so padding above or below the glyph cannot place a caret. Test tmp/paragraph-icon-column-check.cjs.

- Save-file picker override: single selection only, no Ctrl/Shift multi-select or Ctrl+A selection. Entry context menu contains exactly rename / delete (lowercase). Inline rename uses commitFileRename; deletion keeps the filename-erasure animation before removal.

- Title rename: double-click only the rendered name text of a real file or folder to edit inline. Software titles and blank/icon hit areas keep their existing behavior; /house is fixed. Lock the original file extension outside the editable input. Enter commits through commitFileRename, Escape cancels, read-only/collisions remain enforced. Preserve stable IDs, content and descendant paths. Shared implementation: title-rename.js/css.

- Application display names have one source: application-names.js. Keep IDs, saved keys and routing stable; all PC/Phone labels, search/sort names, titles and authored app messages use appLabel/appText. Future renames edit only registry values, never global text replacement. Do not rewrite user files. Regression: tmp/application-names-check.cjs.

- All Cabanon UI controls use square corners. Rounded geometry is permitted only within intentionally drawn symbols, not button/input surfaces. Phone Home short tap always restores normal home at scroll zero; search keyboard pointer events must not reach homepage gesture recognition.

- Software-level changes are shared by PC and Phone: display names, canonical icons, action availability and removal policy must use one source and update both surfaces. Only layout/typography may be device-specific unless the user explicitly requests an exception. applicationNoRemove in application-names.js is the shared no-remove table (initially TIME, DATE); all software menus place remove last and protected software must also reject direct uninstall/removal gestures. See ../docs/APPLICATION-CATALOG.md.
