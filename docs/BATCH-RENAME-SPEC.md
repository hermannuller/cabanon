# cabanon · Batch Rename Specification

**版本：v1.0（2026-10-18）**  
**状态：当前最终设计规范；允许未来按实际使用情况迭代。**

## 1. 总体结构

批量重命名只有两个部分：

1. **FIND**：确定需要处理的字符或字符范围。
2. **DO**：针对 FIND 的结果执行 **REPLACE / CASE / ADD / CLEAN**。

**DELETE 不单设按钮**：REPLACE 的替换内容为空，即删除匹配内容。

FIND 返回原文件名中的一个或多个**位置区间**，而不是只有匹配的文本值。执行前提供实时结果预览，并检验文件名是否合法及是否重名。

默认操作**主文件名**，不包括扩展名（如 `.txt`、`.jpg`）。扩展名是否提供单独编辑入口，尚未确定。

## 2. FIND：字符匹配指令

| 语法 | 含义 | 备注 |
|---|---|---|
| `/n` | 一个数字 | ASCII `0–9` |
| `/a` | 一个英文字母 | `A–Z`、`a–z` |
| `/c` | 一个 CJK 文字字符 | 汉字、日文假名、韩文文字等；具体 Unicode 范围由实现确定 |
| `/i` | 一个不属于数字、英文字母或 CJK 文字的合法字符 | **排除分类**：在合法文件名字符集合内，排除 `/n`、`/a`、`/c` 所匹配的字符；包括空格、标点、符号以及未被上述类别覆盖的其他 Unicode 字符 |
| `/s` | 一个普通空格 | 可以直接输入真实空格，或使用 `/s` |
| `?` | 任意一个字符 | 直接输入 `?`，不需要写成 `/?`；包括数字、字母、文字、空格和符号 |
| `/d` | 一段系统支持的日期格式 | 仅匹配系统预设格式；用户自行决定是否使用，允许误识别和误操作；不读取文件元数据 |

`/t`（制表符）**不纳入文件名 FIND 规范**，因为 Cabanon 文件名不允许制表符、换行和回车。

`/i` 不维护人工逐项列举的字符清单。实现时仅判断某个字符是否属于 **Cabanon 允许的文件名字符**，且**不属于** `/n`、`/a`、`/c`。因此 `/i` 包括常见标点、符号、空格，以及未被这三类收纳的其他语言文字或 Unicode 字符；不能反过来宣称所有 Unicode 字符都能用于文件名。

`/s` 专门匹配一个普通空格；空格同时也属于 `/i`。`/c` 为 CJK 文字类别，采用实现时固定的 Unicode 字符分类表，不做语义语言识别。`

### 2.1 直接文本与连续模式

- 输入 `ABC`：查找实际文字 `ABC`。
- 输入 `/n/n/n`：匹配连续三个数字。
- 输入 `/n /n`：匹配“数字 + 一个空格 + 数字”。
- `/n/n` 与 `/n /n` 的相邻条件不同，空格有实际意义。**在 `|` 出现前，整个表达式是一组连续匹配模式，包含其中的所有普通字符与空格**；`|` 才会开启下一组独立匹配。
- `?` 直接表示任意单字符，例如 `??` 匹配连续两个任意字符；不采用旧写法 `/?`。
- FIND 留空：代表整个主文件名（全局）；ADD 对空 FIND 有专门的插入点规则，见下文。

### 2.2 第 N 次出现：`/数字`

`/N模式` 表示该模式**从左到右第 N 次出现**的匹配；序号从 **1** 开始。

| 表达式 | 意义 |
|---|---|
| `/2ABC` | 第 2 次出现的 `ABC` |
| `/2/n` | 第 2 个数字 |
| `/2?` | 第 2 个任意字符，即第 2 个字符 |
| `/2??` | 第 2 组连续两个任意字符；使用**不重叠**匹配 |
| `/22/n` | 第 22 个数字 |
| `/2/n/n` | 第 2 次出现的连续双数字模式，而非不附加条件的第 2、3 个数字 |

**多字符匹配一律不重叠**：每次从左到右找到一个完整匹配后，从这个匹配的终点之后继续查找下一次。例如 `ABCDE`：`/1??` → `AB`，`/2??` → `CD`，而不是 `BC`。一个 `|` 分组内按整段模式匹配，不把连续的 `?` 分开计数。

**数字歧义**：当匹配对象自身以数字开头时，用非法文件名字符 `:` 消歧。

| 表达式 | 意义 |
|---|---|
| `/2:2` | 第 2 次出现的字面数字 `2` |
| `/22:2` | 第 22 次出现的字面数字 `2` |
| `/2:2026` | 第 2 次出现的字面文本 `2026` |

没有后续模式的 `/22` 不构成完整的查找表达式。无需另外引入 `/+数字`。

### 2.3 取反：`\`

使用 Windows 文件名中不合法的反斜杠 `\` 表示 **NOT／补集**，不使用允许出现在文件名中的减号 `-`。

| 表达式 | 意义 |
|---|---|
| `\/n` | 除数字以外的所有字符 |
| `\/a` | 除英文字母以外的所有字符 |
| `\/2/n` | 除第 2 个数字所占字符以外的全部字符 |
| `\/2ABC` | 除第 2 次出现的 `ABC` 所占字符以外的全部字符 |

这里的“除了”指**原主文件名中未被匹配区间覆盖的位置**，不是仅仅选中其他同类别字符。

### 2.4 并集：`|`

竖线 `|` 连接独立 FIND 表达式，最终取**匹配位置的并集**，重叠位置不重复修改。

| 表达式 | 意义 |
|---|---|
| `/2/n|/a` | 第 2 个数字，以及所有英文字母 |
| `/n|/a` | 所有数字和英文字母 |
| `\/n|/2/n` | 非数字字符，以及第 2 个数字 |

`|` 右侧不继承左侧的 `/N` 修饰。

### 2.5 日期：`/d`

`/d` 是**可选的主动查找指令**：只识别系统实现时明确支持的日期格式，对找到的文本做日历合法性验证。它不会自动扫描或修改所有文件名，也不读取文件的创建/修改时间等元数据。

首版建议支持以下四种格式（实现时固定为可测试的模式表）：

- `YYYY-MM-DD`，例如 `2026-10-18`
- `YYYYMMDD`，例如 `20261018`
- `YYYY.MM.DD`，例如 `2026.10.18`
- `YYYY_MM_DD`，例如 `2026_10_18`

系统**不保证语义准确**：例如八位编号可能恰好是一段合法日期。用户只有主动输入 `/d` 才启用该匹配，并通过实时预览自行判断，允许误操作。日月年等歧义格式、英文月份等不自动猜测；未列入实现格式表的日期不匹配。

## 3. DO：四项操作

### 3.1 REPLACE（替换，也承担删除）

- 将 FIND 找到的内容替换成用户输入的文本 B。
- **B 为空 = 删除**，不提供独立 DELETE。
- FIND 只有一个匹配区间：就地替换。
- FIND 有**多个匹配区间**：删除原匹配内容，将输入的新内容**只放在主文件名开头一次**，而不是在每个匹配点重复放置。**不提供更改该插入位置的选项**；需要进一步处理时由用户执行下一步操作。
- FIND 留空：以整个主文件名为替换范围；FIND 与替换内容同时留空会产生空文件名，因此禁止执行。
- 替换内容允许用 `/q` 生成序号。

例：`A1B2C3.txt`，FIND `/n`，REPLACE `X` → `XABC.txt`（删除全部数字，将一个 X 放在开头）。

### 3.2 CASE（大小写）

三个可直接点击的文字按钮：

| 按钮 | 行为 |
|---|---|
| `TT` | 全大写 |
| `tt` | 全小写 |
| `Tt` | 单词首字母大写 |

只修改 FIND 选中的范围；FIND 留空时作用于整个主文件名。具体 Unicode 大小写、单词边界规则由实现确定。

### 3.3 ADD（添加）

- 用户输入要添加的文本。
- 选择 **BEFORE（前）** 或 **AFTER（后）**。
- FIND 有匹配：在**每个匹配区间**之前或之后添加相同内容。
- FIND 留空：BEFORE = 文件名开头；AFTER = 主文件名结尾（扩展名之前）。
- 添加内容也可包含 `/q` 序号模板。

例：`A12B3.txt`，FIND `/n`，ADD `a`，AFTER → `A1a2aB3a.txt`。

### 3.4 CLEAN（连续重复字符合并）

**最终仅保留一个清理功能：将指定字符连续重复的片段压缩为一个字符。**

| 原名 | 选定字符 | 结果 |
|---|---|---|
| `A   B  C` | 空格 | `A B C` |
| `BOOK___001` | `_` | `BOOK_001` |
| `A---B` | `-` | `A-B` |
| `Hello!!!` | `!` | `Hello!` |
| `BOOK0001` | `0` | `BOOK01` |

- 可以指定普通空格，也可以指定其他一个字符。
- 不保护正常单词中的重复字母；执行后造成不合意的变化由用户自行判断。
- **已删除“紧凑重排序号”功能**（例如 `1,5,9 → 1,2,3`），不再作为 CLEAN 项目。
- CLEAN 与 FIND 的组合方式尚未完全规定；最直接的实现是对所指定的字符在主文件名内做连续压缩，界面预览结果。

## 4. 序号模板：`/q`（仅用于输出）

**`/q` 不是 FIND 操作符，不能用来识别旧文件名中的“序号”。** 它只在 REPLACE 或 ADD 的输出文本中生成批量编号。

| 输出模板 | 生成序号示例 |
|---|---|
| `/q` | `1`、`2`、`3`… |
| `/q/q` | `01`、`02`、`03`… |
| `/q/q/q` | `001`、`002`、`003`… |
| `/q/q/q/q` | `0001`、`0002`、`0003`… |

连续几个 `/q` 就表示**最低位数**。不足左侧补零，超出宽度不截断。按照当前参与批量操作的文件排列顺序生成编号；起始值默认为 1。调整起始值、排序方式的 UI 尚未确定。

## 5. 文件名合法性与操作安全

- Cabanon 采用 Windows 兼容文件名约束；禁止 `\ / : * ? " < > |`、ASCII 控制字符（含制表符、换行、回车）。
- 文件名不得为空，不得单独是 `.`、`..`，不得以空格或句点结尾；还需处理 Windows 设备保留名。
- Unicode 以 NFC 规范化；在同一文件夹中，以大小写不敏感方式检测重名。
- 批量操作之前展示改名前后预览；发现非法名或冲突时阻止有问题的改名，避免隐式覆盖。
- FIND 没有匹配时，该文件保持原名，不视为语法错误。

**注：** 不合法文件名字符可用于 FIND 表达式语法，但**最终生成的文件名**仍必须合法。

## 6. 解析与执行的确定规则

1. **先分组，再匹配**：以 `|` 分隔独立的查找组；组内所有字符（包括真实输入的空格）按原样构成一个连续模式。
2. **匹配不重叠**：每组自左向右扫描，找到一次完整匹配后，从本次匹配末尾继续扫描。`/N` 选择该组模式的第 N 次完整匹配。
3. **局部取反**：组首的 `\` 对紧随其后的整组查询结果取补集；`|` 对各组最终结果求并集，不引入 AND、括号或其他嵌套优先级。
4. **统一位置集合**：把匹配范围转为原始主文件名的字符位置集合；并集去重；REPLACE 对多个匹配区域按其既定特殊行为执行。
5. **执行一次，不递归**：所有 FIND 都在**修改前的原文件名快照**上执行一次；DO 的新生成字符绝不再次进入本轮 FIND。`/q` 是输出模板，按参与操作的文件顺序仅展开一次，不会反复匹配或编号。
6. **无匹配即跳过**：格式有效但找不到的文件保持不变；语法不完整或输出文件名非法则不执行相应改名；操作前实时预览，并检查冲突。
7. **主文件名范围**：匹配默认不包括扩展名。所有字符位置与匹配次序均相对于主文件名计算。

这些规则是为避免歧义、重复修改和循环执行而固定的实现约束，而不是新增的 UI 功能。

## 7. 明确放弃的设计

- 不为批量查找引入完整正则表达式语法。
- 不使用 `/+数字` 区分字符位置和出现次数；统一为 `/N模式` 的第 N 次出现。
- 不使用 `-` 作 NOT，因为 `-` 是合法文件名字符；使用 `\`。
- 不用 `/q` 查找已有序号；它只负责**生成**序号。
- 不设独立 DELETE；替换内容留空即删除。
- 不设“紧凑重排序号”CLEAN 按钮。
- 不为文件名匹配加入 `/t` 制表符，也不允许文件名包含换行、回车或制表符。
- 不使用 `/?` 表示单字符通配符，直接使用 `?`。

## User override — 2026-10-18: automatic collision numbering

Batch results may deliberately share the same requested name. Show the actual allocated names in preview and enable OK for legal results: `same.txt`, `same_1.txt`, `same_2.txt`, etc. Numbering is scoped to the final containing directory, respects full case folding and skips occupied names. Existing unselected entries and selected entries retaining their name take precedence; never overwrite their contents. Illegal or empty output names still block application. This supersedes the prior instruction to reject a batch merely because of duplicate requested names.

FIND syntax validation is separate from final filename validation. `/a` in FIND matches English letters; an empty replacement deletes them. If that leaves an empty base, report the result-name error, not an illegal FIND character. `/q` is the output numbering template; literal `/a` in output remains invalid as a filename because of the slash.


## 已实现交互补充（2026-10-19）

右侧预览列表可按住文件图标，用左键上下拖拽排序；文字不是排序把手。预览顺序控制 `/q` 和自动重名 `_n` 编号，拖动后立即重算。仅改变本次批量处理顺序，不改变文件夹排序。Esc 取消本次拖动并恢复此前顺序。完整用户说明见 HELP! → Rename。
