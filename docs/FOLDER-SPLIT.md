# PC folder window groups

- Ctrl+T adds a folder window to a window group at the current path and focuses it, up to four panes under one title bar. Two panes split left/right. Three panes use two top cells and a full-width bottom cell. Four panes use a 2×2 grid. Adding, moving out or closing panes resets the layout to equal row/column divisions.
- Ctrl+T with four panes opens an independent window at the focused pane's path, just like Ctrl+N.
- Physical cell positions stay fixed when focus changes; explicit left/right-button dragging swaps cells or transfers a pane between groups. Each pane owns its list, selection, scroll position and navigation history. The active pane is first in DOM order (using state-preserving `moveBefore`) so existing window-level commands address it.
- The shared title bar follows the focused pane. The inactive pane shows its full path as a compact 12px/18px single-line hint inside its upper-left content area, immediately below the title bar. The hint overlays the files without reserving space or shifting their positions; partial overlap is intentional.
- Focused and inactive panes share the same L2 background. Inactive text/icons use L6 gray; keep L3 inactive selection and the L4 separator. Do not add colors or dimming overlays.
- Drag the vertical separator to resize both columns together; drag the horizontal separator to resize both rows together. No independent cell edges are movable. With three panes the vertical line only divides the top row. Preserve at least 160px width / 112px height when space permits. Escape rolls back a drag. Arrow keys on the corresponding separator adjust it; Home restores its equal division.
- Each grouped pane has a 42×40 close button at its upper-right, sharing the title-bar close symbol/size and title-bar background. Its button closes only that pane; closing an inactive pane preserves the active pane. The shared title-bar × closes the entire window group. Ctrl+W continues to close the focused pane. Survivors compact in physical row-major order through the 4→3→2→1 layouts. Single-window content has no extra left inset, and grouped content has no outer margins. Collapsing to one pane removes the pane close control and restores the ordinary title-bar close behavior.
- File hit areas and drag origins remain governed by FILE-POINTER-CONTRACT.md.
- Left- or right-drag from pane whitespace into another pane in the same group shows `←→ windows`. Release there exchanges only the source and destination cells, including diagonal cells, while preserving focus, paths, selections, history and scroll. Other cells stay in place.
- Drag into another folder window or window group to move the source pane into that group (`+ windows`). A single target window becomes a two-pane group. A four-pane target rejects the move (`X`) and leaves the source unchanged. Target detection uses the visible window under the pointer, independent of pointer capture.
- Left-drag outside the source window onto desktop space or unrelated software to form an independent folder window (`window`), decreasing the source group by one. Left-dragging an already independent folder into free space repositions that window without duplication. Right-dragging outside now closes the dragged pane immediately with red `close` feedback and no prompt. Moving a single window's only pane into another group removes the old window shell.
- Left- or right-drag onto a folder title-bar × or pane × closes the dragged source pane, not the pane under the target button and not the entire source group. Closing feedback is lowercase red `close`; release performs the close without prompting. Escape, returning to a non-close target, pointer cancellation and focus loss abort as before. Ordinary file-origin drags do not become window-close gestures.
- Transferring a pane moves its real list and editor DOM, preserves path/history/selection/scroll, and transfers editor resize-observer ownership. Navigation callbacks are rebuilt for the destination window, preserving width, expansion and scroll. No file entries are copied, moved, created or removed by grouping.
- Returning to the source, Escape, pointer cancellation or focus loss does not regroup. File-origin drags keep their existing behavior. Crossing into a window action takes ownership from box selection and never applies its file action. Same-pane drags remain normal selection gestures. Phone interactions remain unchanged.
- DOCK hover expands every group into individual full-path rows, including duplicate paths, with an independent × at each row's right edge. Selecting a row restores its host window and focuses that pane; × closes that pane through normal close behavior. Counts and open lists refresh when panes change.
- Right-clicking a DOCK icon opens a single `close all` action, anchored above the icon exactly like the hover list. Clicking closes all windows and grouped panes for that icon immediately, without confirmation or save prompts. This explicit exception takes the normal quit/cleanup path for dirty documents; unsaved content is not written over source files, while applications may retain their normal local drafts. Ordinary editor ×, Ctrl+W and Ctrl+Q retain their existing close/save rules; folder group/pane buttons and drag-close actions follow the rules above.
