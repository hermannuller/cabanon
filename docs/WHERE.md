# WHERE — 图恩第一版

WHERE 从现有软件列表打开，PC 和 Phone 共享搜索解析、地点索引、路线计算与地图样式。HELP 的 `/house/Cabanon.help`（用户称 `/house/cabanon.help`）有独立的 `map spells` 设计条目；原有正文和独立草稿保留。

## 已接入的搜索

- 名称、道路名、门牌地址搜索；原始名称来自图恩 OSM 快照。中文类别支持酒店、青旅、餐厅、咖啡馆、医院、学校、火车站、药店、超市和城堡。
- `图恩 /酒店`：图恩快照范围内搜索。具体地点后的 `/类别` 默认取周边直线距离 1000 米，可使用 `:距离<=500米` 改变范围。
- `Thun > Spital Thun :步行`：顺序经过地点，显示真实路网路径、估算距离和耗时。各段可以分别指定 `:步行`、`:骑行`、`:驾车`；未指定的段默认步行。
- `Spital Thun *酒店 :步行 :耗时<=30分钟`：候选酒店 → Spital Thun，按耗时排序。保留方向，不能把反方向耗时当成抵达耗时。
- `Thun > Spital Thun ~酒店 :距离<=200米`：距已算路线的直线距离范围，默认 200 米；第一版不计算绕路耗时。
- `(Thun & Spital Thun) /酒店 :步行 :耗时<=30分钟`：多个独立起点到候选地点，各自符合约束，按最慢一方耗时最少排序；各起点可分别指定交通方式。
- `!名称` / `!类别` 排除，双引号保护名称中的操作符，交通方式用 `|` 表示允许的选择。
- `:耗时`、`:距离` 支持 `<`、`<=`、`=`；路线比较使用实际估算值，`=` 对秒数／米数取整后精确比较。区域／沿途查询中的距离表示搜索半径。

输入补全和方向键选择共用一个搜索框；Enter 执行，Escape 收起结果。选择结果在地图中显示地点和相关路线。`map spells` 按钮直接打开 HELP 中相应条目。

比较使用键盘字符 `<`、`<=`、`=`、`>`、`>=`；双字符操作符必须连续输入，不自动替换成数学字形。词法分析先把 `<=` 和 `>=` 识别为完整操作符；在 `:条件名` 后解释比较，条件外的 `>` 表示下一段路线。例如 `A > B :出发>=18:00 > C :步行` 解析为三地点、两段路线，出发条件属于到 B 的一段。语法可解析不代表时刻筛选已经接入。

## 数据与计算边界

底图是 OSM 城区快照，署名与版权链接始终显示。没有在线底图、全球地名搜索或实时刷新。地址位置使用建筑几何中心，街道结果使用该街道所覆盖道路的中心；不声称是精确入口。

本地路由使用补充的图恩 `highway` 数据构图，保留真实 OSM 节点 ID，防止坐标相近但不同的立交节点被错误连通。按交通方式检查通行限制，驾车与骑行检查单向，驾车参考限速或道路类别速度。步行采用 1.4 m/s，骑行 4.2 m/s；起终点到可用路网的接驳按步行估算。不计算实时拥堵、信号等待、坡度和转弯耗时。没有符合条件的连通路线时显示错误，不用直线冒充路线。

未接入 GTFS／实时公交数据，因此 `:地铁`、`:公交` 明确报出不可用。出发／到达时刻、营业筛选、复杂分组、任意布尔条件等仍是设计语法，不能执行时明确提示，不静默忽略。这里是可使用的地图原型，不提供逐向实时导航。

## 实现

- `home/where-model.js`：语法、查询语义、路网构图与最短时间路径。
- `home/where.js`：PC 窗口、Phone 挂载、补全、搜索结果和状态保存。
- `home/where-map.js` / `where-map.css`：共享地图组件；独立 SVG ID，隔离系统图标的描边规则。
- `home/where-data.js`：压缩 OSM 快照，开箱可用。`tools/import-where-data.cjs` 从已下载数据重建；网络补充输入可作为第三个参数。
- `tools/build-where-map.cjs`：从已审核的图恩样张重建地图组件。

地图保留 L1 陆地底色、L2 森林、L4 50% 不透明度实心建筑、水域 L4 底与 L1 1px 斜线（屏幕间隔 8px）、L2 道路、L4 铁路与 L1 勾边。路线使用 L4 实线配 L1 勾边。颜色继承当前主题。
